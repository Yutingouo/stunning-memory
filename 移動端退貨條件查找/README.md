# 退貨條件查找｜新手使用說明

這是一個用來查詢廠商退貨條件的小工具。輸入廠商名稱或代碼、商品到期年月，就能查看是否到了可以通知退貨的月份。

**只想使用的人，先看第 1～3 節即可。不需要先學寫程式，也不需要安裝 Codex。**

## 1. 我應該開哪個檔案？

| 你的情況 | 請使用 |
|---|---|
| 電腦使用完整專案 | 解壓縮整個資料夾，再開啟 `index.html` |
| Android 手機離線使用 | 解壓縮 `return-rule-finder-mobile.zip`，開啟裡面的 `return-rule-finder.html` |
| 電腦使用單檔離線版 | 開啟 `dist/return-rule-finder.html` |
| 只想測試，不使用實際資料 | 開啟 `dist-demo/index.html`，或使用 `return-rule-finder-demo.zip` |
| 已有部署好的網站 | 用瀏覽器開啟網站網址 |

根目錄的 `index.html` 會使用旁邊的程式、樣式與資料檔案，請保留整個資料夾。單檔離線版則已把程式、樣式和資料放進同一個 HTML 檔。

### 在另一台 Windows 電腦開啟

1. 在 GitHub 儲存庫點選 **Code → Download ZIP**，或把整個專案資料夾複製到另一台電腦。
2. 對 ZIP 按右鍵，選擇「解壓縮全部」。不要直接在 ZIP 裡操作。
3. 進入解壓縮後的專案資料夾，找到 `index.html`。
4. 按右鍵，選擇用 Edge 或 Chrome 開啟。
5. 若經常使用，可以為這個檔案建立桌面捷徑。

直接開啟檔案即可使用內建資料；不需要先執行指令，也不需要安裝 Node.js 或 Python。

### 在 Android 手機離線使用

1. 把 `return-rule-finder-mobile.zip` 傳到手機並下載。
2. 在手機的「檔案」或檔案管理工具中解壓縮。
3. 找到 `return-rule-finder.html`，選擇用 Chrome 等瀏覽器開啟。
4. 如果只看到預覽畫面，請先下載、解壓縮，再使用「開啟方式」選擇瀏覽器。

離線版不需要連到電腦，電腦也不必保持開機。拿到新版 ZIP 時，請解壓縮到新的資料夾，確認開啟的是新檔案。

## 2. 怎麼查詢？

1. 輸入廠商代碼或名稱。獨立測試版可以輸入 `T001`。
2. 輸入商品的「到期年月」，例如 `2027/05`、`2027-05` 或 `202705`。
3. 確認畫面上的「基準年月」。系統會自動帶入裝置目前的年月。
4. 如果畫面要求選擇品項，例如水或粉，請先選擇。
5. 按「查詢」，查看狀態、可通知退貨年月與原始退貨規則。

同一個代碼或名稱可能找到多筆資料，請核對結果中的廠商與規則。

## 3. 黃色、綠色、紅色代表什麼？

系統先算出「到期年月距離基準年月還有幾個月」，再和廠商指定的退貨月數比較。

| 顏色 | 畫面文字 | 意思 |
|---|---|---|
| 黃色 | 尚不可退貨 | 剩餘月數大於指定月數，還沒到通知月份 |
| 綠色 | 可以通知退貨 | 剩餘月數恰好等於指定月數 |
| 紅色 | 不可退貨 | 剩餘月數小於指定月數，已超過通知月份；或廠商標示禁退 |

**可通知退貨年月＝商品到期年月－廠商指定退貨月數。**

例如商品到期日是 **2027/05**，廠商規定 **4 個月**，可通知退貨年月就是 **2027/01**：

| 基準年月 | 剩餘月數 | 查詢結果 |
|---|---|---|
| 2026/10 | 7 個月 | 黃色：尚不可退貨，還要等 3 個月 |
| 2027/01 | 4 個月 | 綠色：可以通知退貨 |
| 2027/02 | 3 個月 | 紅色：不可退貨，已超過 1 個月 |

系統以「年月」計算，不計算天數。若規則沒有明確月數，例如要通知業代或依商品確認，會顯示「需要人工確認」，請閱讀原始條件。

## 4. 廠商資料是哪幾個檔案？

主要有三個：

| 檔案 | 用途 | 平常怎麼處理 |
|---|---|---|
| `source.xlsx` | 原始 Excel 資料 | 修改資料時，優先編輯這個檔案 |
| `vendors.json` | 網站讀取、手動匯入的資料 | 由更新工具產生 |
| `vendors-data.js` | 直接開啟網頁時使用的內建資料 | 由更新工具產生，也會包入離線 HTML |

**離線 HTML 和手機 ZIP 也包含廠商資料。** 即使刪除 Excel，這些成品仍可能保留原始內容。

## 5. 修改 Excel 後，怎麼更新？

這一節是給維護資料的人。只使用網頁或離線版的人可以跳過。

### 第一次在新電腦維護資料

需要先準備以下工具，並讓它們能在終端機中執行：

- Python：讀取 Excel。
- Python 的 `openpyxl` 套件：在終端機執行 `python -m pip install openpyxl`。
- Node.js（含 npm）：產生手機離線包及其他版本。

更新工具會先找原開發電腦的工具位置，找不到時改用系統的 `python` 和 `node`。如果顯示找不到指令，請先確認安裝及 PATH 設定。

### 日常更新步驟

1. 先備份原本的 Excel 和手機 ZIP。
2. 修改 Excel，保留原本欄位，例如廠編、廠商名稱、退貨效期和聯絡資訊。
3. 將檔案存成 **`source.xlsx`**，放在和 `index.html` 相同的資料夾。請使用 `.xlsx` 格式。
4. 存檔後，雙擊 **`更新廠商資料.bat`**。
5. 等待視窗出現 **`Update completed`**，才表示資料與手機包都更新完成。
6. 電腦重新開啟或重新整理 `index.html`。
7. 手機則接收新版 `return-rule-finder-mobile.zip`，重新解壓縮並開啟。

這個批次檔會先產生 `vendors.json` 和 `vendors-data.js`，再重新產生離線 HTML 和手機 ZIP。

如果出現 `Data was updated, but mobile zip build failed`，代表資料已更新，但手機包未完成，請先處理錯誤再傳檔。

### 網站版與離線版的更新差別

- **直接開啟根目錄 HTML**：使用內建的 `vendors-data.js`，所以也要更新這個檔案。
- **網站版**：會優先讀取網站上的 `vendors.json`，讀不到時使用內建資料。資料變更後，請同步部署 `vendors.json` 和 `vendors-data.js`。
- **手機單檔離線版**：資料包在 HTML 裡，需要重新打包、重新傳檔。
- **畫面上的手動匯入**：可用於當次套用 JSON；目前程式重新開啟時仍會載入網站或內建資料。若要持續使用新版，請更新正式資料檔或重新打包。

## 6. 示範版要怎麼放到網路上？

**正式版與示範版請分開管理。公開展示只使用虛構資料。**

專案提供獨立測試版，裡面有 5 筆虛構廠商，包含月份判斷、禁退、人工確認及不同品項的測試案例。

如果需要重新產生測試版，在專案資料夾開啟終端機，執行：

```powershell
npm run build:demo
```

輸出會放在 `dist-demo`。將**這個資料夾裡面的檔案**放到專用測試網站即可。這個指令不會自動上傳 GitHub，也不會重新產生 `return-rule-finder-demo.zip`；如需 ZIP，請把新版 `dist-demo` 的內容自行壓縮。

建議另外建立示範用儲存庫，僅上傳測試版內容。正式資料的儲存庫維持私人，不要為了展示直接公開整份正式專案。

如果你自己已經準備好示範版 `source.xlsx`、`vendors.json` 和 `vendors-data.js`，請保留那些示範檔案，避免用本地正式資料覆蓋。

## 7. 怎麼在 GitHub 網頁更新程式？

以下適用於保留完整專案結構的儲存庫。

1. 進入 GitHub 裡的專案資料夾，確認目前位置包含 `index.html`。
2. 點 **Add file → Upload files**。
3. 選擇要更新的程式檔，例如 `app.js`、`index.html`、`styles.css`、`service-worker.js` 和 `README.md`。
4. 確認上傳清單，填寫修改說明，再按 **Commit changes**。
5. 若要更新工具程式，先進入 GitHub 的 `tools` 資料夾，再上傳對應檔案，例如 `build-single-file.cjs` 或 `build-demo.cjs`。
6. 若新增或修改 npm 指令，也要在專案資料夾更新 `package.json`。

同路徑、同檔名的檔案會被更新。只上傳程式檔，不會自動更新已產生的離線 HTML、ZIP 或部署網站。

**上傳前請特別核對資料檔、Excel、HTML 成品和 ZIP 使用的是正式資料還是示範資料。**

## 8. 常見問題

### 手機打不開電腦上的預覽網址

`127.0.0.1` 代表正在使用的那台裝置，手機輸入這個位址不會連到電腦。

若要透過區域網路連線，電腦要啟動預覽服務，手機與電腦之間也必須能互通；電腦插網路線、手機連 Wi-Fi 可以使用，但仍取決於路由器、網路隔離和防火牆設定。

如果只是想在手機查詢，直接使用 Android 離線包即可。

### 更新後仍看到舊畫面

- 本機檔案：確認開啟的是新版資料夾，並重新開啟檔案。
- 手機離線版：確認已重新打包、傳送並解壓縮新版 ZIP。
- 網站：確認程式已部署完成，再重新整理；必要時請維護人員檢查瀏覽器快取。

### 找不到廠商，或顯示資料不完整

確認使用的版本是否包含該廠商，以及 Excel 是否已存檔並成功更新。測試版只有虛構資料，無法查詢實際廠商。

## 9. 維護者指令速查

請先安裝 Node.js，並在**有 `package.json` 的專案資料夾**開啟終端機。

| 指令 | 用途 | 產生結果 |
|---|---|---|
| `npm run check` | 檢查 JavaScript 語法 | 不會改資料 |
| `npm run preview` | 啟動本機網頁預覽 | `http://127.0.0.1:4173/` |
| `npm run build:single` | 以目前資料產生手機離線版 | `dist` 和 `return-rule-finder-mobile.zip` |
| `npm run build:live` | 以目前資料產生網站部署版 | `dist-live` 和 `return-rule-finder-live.zip` |
| `npm run build:demo` | 產生只有虛構資料的網路測試版 | `dist-demo` |

預覽服務啟動後請保留終端機視窗；結束時按 `Ctrl+C`。一般查詢和這些打包指令不需要先執行 `npm install`；原生手機 App 包裝是另外的流程。

更多平台資訊可參考 [PLATFORM.md](./PLATFORM.md)。
